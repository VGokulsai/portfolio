Work

Each of these came out of something that was annoying me. None of them came out of looking for a market.

painpoint-finder Python2026

Checks whether a person actually has the problem you think they have, then drafts the message. It never sends it.

Screened 963 posts to test one assumption. Most of what people call a pain point does not survive that.
apisurface Python2026

Diffs the public API of an npm package between two published versions, reading the shipped code rather than the changelog.

Found removals in Stripe's types that the release notes never mentioned. 38 tests, no network in any of them.
cloud-pet Python2026

A desktop companion for Windows with no dependencies at all. It also ranks the day, counts who has not replied, and speaks when a coding session finishes.

Talks to Windows through ctypes directly. A tool that opens with a missing-package error is a tool nobody runs.
publicsearch Python2026

The search layer, pulled out on its own so anything else can use it.

How I work

Three rules I did not have when I started, and got wrong enough times to write down.

Blocked is not empty

A source that could not be read must never look like a source with nothing in it. Almost every wrong answer I have shipped was that.

Build before researching

I killed eight ideas with research and built none of them. Now the prototype comes first and the research checks it.

Read the primary source

No number from a blog post or a vendor page. Either I have read where it came from, or I say it is unverified.
